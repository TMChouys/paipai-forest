   | 誰 | 評量什麼 | 形式 | 通過標準（💡） |
   |---|---|---|---|
   | 慢慢館長 | **認知**：懂不懂、會不會預測結果 | 選擇題：記憶 → 理解 → 預測輸出（每概念 2～3 題，班級版再加課本習題） | 答對才算「讀懂這一課」 |
   | 派派狼 | **實作**：寫不寫得出來 | 委託任務，依四個階段評分：① 能執行 ② 結果正確 ③ 用對方法 ④ 好讀好改（見「二之一」） | ✅ **四個階段都過＝滿分**，才送家具、解鎖下一個商品 |

   | 三花奶奶 | **總結性評量**：一個階段學完了沒 | 四關考核，見「二之二」 | ✅ **全部答對**才過關 |
   | 黑貓弟弟 | 不打分數，**考完檢討** | 每一題 ✓／✗、正確答案、為什麼、程式要改哪裡 | — |

## 二之一、派派狼的實作評分表（✅ 2026-11-08：**滿分才有家具**）

### 1. 每個委託都照四個階段評分

派派狼一個階段一個階段檢查，**四個階段都通過＝滿分**，拉拉老闆才送家具。
沒滿分可以一直重做；派派狼會說是哪一個階段沒過、差在哪裡（派派兔的提示也會對準那個階段）。

| 階段 | 評估的技能 | 怎麼檢查（遊戲的檢查器） | 沒過時派派狼怎麼說（💡） |
|---|---|---|---|
| ① 能執行 | 語法正確：括號、引號、冒號、縮排、半形符號；執行時不出錯 | syntax.*、runtime.* | 「程式跑不起來喔，第 3 行少了右括號。」 |
| ② 結果正確 | 輸出（含格式、空白）和動作都符合要求；**換一組數字（隱藏測資）也要對**，不能直接寫死答案 | output.*、goal.*、action.*，含隱藏測資 | 「這組對了，換成 5 袋就不對了，是不是把答案寫死了？」 |
| ③ 用對方法 | 用到這個委託指定的概念（例如要用 for，不能寫五次 print；要用給定的變數） | rule.must_use、rule.given_var、rule.var_in_print… | 「答案對了，但這次要練 for 迴圈喔。」 |
| ④ 好讀好改 | 變數名稱有意義、沒有多餘的程式；第 9 章以後函式要有說明、第 10 章以後要處理錯誤 | 💡 新增規則：rule.name、rule.unused、rule.docstring…（目前檢查器還沒有） | 「可以了！不過 a、b、c 誰看得懂？取個好名字。」 |

- **滿分**＝①②③④ 都過 → 拉拉老闆送家具。
- ✅ **④「好讀好改」從第 1 章就算分**（2026-11-08 確認）。
- ✅ **派派狼的評分單**：每一章的檢核項目一條一條列出來，每條都有**清楚的提示**，
  完成的打 **✓**、還沒完成的打 **✗**；全部 ✓ 才是滿分。沒過的那一條，旁邊直接寫要怎麼改。
- 目前遊戲的做法（要改）：①② 都過就送家具（2 星），③ 有問題只少一顆星，④ 還沒檢查。

**評分單的樣子（💡 以第 2 章〈市集的會員卡〉為例）**

| 階段 | 檢核項目 | 結果 | 提示 |
|---|---|---|---|
| ① 能執行 | 沒有語法錯誤（括號、引號都是半形、成對） | ✓ | — |
| ① 能執行 | 執行時沒有出錯 | ✓ | — |
| ② 結果正確 | 輸出和拉拉老闆要的一模一樣 | ✓ | — |
| ② 結果正確 | 換一位客人的名字也對 | ✗ | 你直接寫了 "派派鼠"，換成別人就錯了。改用變數 name。 |
| ③ 用對方法 | 用變數存會員的名字和點數 | ✓ | — |
| ④ 好讀好改 | 變數名稱看得懂 | ✗ | x 是什麼？改成 points 會比較清楚。 |

→ 2 個 ✗，還不是滿分。派派狼：「差兩個地方，改完再拿來給我看。」

### 2. 各章的技能檢核表（③④ 階段要看什麼）

每一格的項目都會變成評分單上的一條檢核（✓／✗＋提示）。

| 章 | ③ 用對方法：要看到的寫法 | ④ 好讀好改：要做到的習慣 | 常見錯誤（派派兔的提示重點） |
|---|---|---|---|
| 1 會說話 | print() 一行一句；需要時用 sep / end | 一句話一行，不要擠在一起；需要說明的地方用 # 註解 | 全形括號引號、少引號、print 拼錯 |
| 2 記住東西 | 用變數存值，再用變數輸出；用 int() / str() 轉換型態 | 變數名稱看得懂（acorns，不是 a） | 數字和字串相加、變數名稱打錯 |
| 3 算一算 | 用運算式算出來，不手算；// % 用在平分和餘數 | 算式加括號讓順序清楚 | / 和 // 混用、= 和 == 混用 |
| 4 聽懂別人 | input() 拿資料、轉成數字；f-string 組句子 | 提示文字清楚；輸出格式整齊 | 忘了 int(input())、f-string 少 f |
| 5 做決定 | if / elif / else 涵蓋所有情況；條件用比較和邏輯運算 | 縮排一致；條件由小到大或由大到小排好 | 冒號、縮排、else 位置、邊界值（>= 或 >） |
| 6 重複做 | 用迴圈，不重複貼程式；range 的起止正確；while 一定會停 | 迴圈變數名稱有意義；累加變數先設初值 | 差一次（off-by-one）、無窮迴圈、累加放錯位置 |
| 7 收藏冊 | 用串列存一組資料；用迴圈走訪；用方法增刪排序 | 串列名稱用複數（photos）；不要一個一個寫索引 | 索引從 0 開始、超出範圍、邊走訪邊刪除 |
| 8 價目表 | 用字典對應「名稱→價錢」；查不到用 get / in | 鍵的名稱一致 | KeyError、把字典當串列用 |
| 9 工匠的工具 | 把重複的步驟寫成函式；用參數和 return | 函式名稱說明它做什麼；加一行說明 | 忘了 return、函式裡改不到外面的變數 |
| 10 圖書館的紀錄 | 用 with open 讀寫檔；用 try / except 處理錯誤輸入 | 檔名、編碼寫清楚；錯誤訊息對使用者友善 | 忘了關檔、讀寫模式用錯、except 全部吞掉 |
| 11 寶庫的謎題 | 自己寫出搜尋、排序的步驟（不能直接用 sort / index） | 每一步加註解說明在做什麼 | 二分搜尋的範圍更新錯、排序少比一輪 |

**✅ 串起整條故事：「三個老朋友 → 三個新朋友」**

  派派鼠在筆記本最後一頁寫下自己的第一句話，傳承下去。

## 七、為什麼收集家具會推進劇情，一直到最後的解謎？

**問題**：現在家具只是獎勵，收集家具和爺爺的箱子、寶庫的謎題沒有關係。

**✅ 確定（2026-11-08）：把家具和「爺爺的樹屋」連起來，讓家具變成解謎的線索**

1. **家具清單＝爺爺的樹屋原本的樣子**
   - 大牙師傅的師父當年和爺爺一起蓋樹屋，留下一本「樹屋家具清單」，每一頁是爺爺家一個角落的舊照片（派派鼠開場拿的照片就是其中一張）。
   - 收藏冊多一頁「爺爺的樹屋」：11 個角落，每個角落是一套家具（例如「窗邊的讀書角」＝蘑菇小燈＋地毯＋小椅子）。
2. **每一章的委託都拿滿分 → 這一章的那套家具到齊**
   - 家具是拉拉老闆的貨：基礎的貨是單一概念任務送的，進階家具要大牙師傅用基礎的貨做（＝章末複合任務）。
3. **把家具擺回照片裡的位置 → 找到一把鑰匙**
   - 套組擺好，那個角落就和爺爺的照片一樣了，藏在家具裡的東西就出現（例如地毯下面、燈罩裡、書櫃後面）：**箱子的一把鑰匙**。
4. **鑰匙打開箱子的一道鎖 → 讀到爺爺的一頁筆記 → 筆記指向下一個地方或下一個人**
   - 例如第 5 章的筆記是派派森林的地圖，下一章就跟派派狼出遠門。
5. **最後的解謎用到所有收集到的東西**
   - 11 把鑰匙打開箱子，最後一頁寫著：「照片放在寶庫最深處，第○排第○格。」
   - 寶庫的書架有很多格，要用家具清單上的年份**排序**、再用**二分搜尋**找到那一格（第 11 章的演算法），
     三花奶奶開最後一道門，裡面就是三個老朋友年輕時的冒險照片。

整條線：**學會 → 滿分 → 家具到貨 → 擺回爺爺的樣子 → 找到鑰匙 → 開鎖讀筆記 → 前往下一個地方 → 最後的謎題**。
所以布置家裡不只是裝飾：派派鼠一邊學習，一邊把爺爺的家找回來。
